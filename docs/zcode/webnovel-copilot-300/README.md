> 任务名称：`webnovel-copilot-300`
> 方案日期：2026-09-03 · 基座：本仓库 `tmp/zcode` 分支 **v7.1.0**（ZCode 原生插件）· 目标版本线：**v8.0.0「作者主权 + 300 章连贯」**（本仓库独立演进线，与上游 lingfengQAQ 仓的 v8/dsh 概念无关）
> 宗旨：**ZCode + webnovel-writer 为长篇中文网文作者提供全方位辅助**——最大程度帮作者连贯写到 300 章以上，并用 AI 辅助玄幻技能/武力值等设定创作、支撑作者想象力。

## 一句话方案

在 v7.1.0 基座上加一层**作者主权治理层（L7）**：作者写入是真值、AI 写入是提案；git 是正典、合同与索引是可重建的编译产物；大纲/素材/战力体系全部走「草稿 → 作者确认 → 分阶段冻结 → 修改走影响分析」生命周期；同时补齐 300 章连贯性八项差距与设定工坊四生成器，并把成稿质量杠杆（上一轮审阅的 W1-W10）并轨进同一条实施队列。

## 核心主张（七条，全文展开见 01）

1. **作者是唯一真源**：作者写入直接生效并留账；AI 写入一律是提案，采纳（settle）才进正典。写章门禁只约束 AI 路径，作者路径免拦截。
2. **修改触发记录 = git + author-sync**：不靠 hooks 拦截，靠会话启动时扫描 git diff → 语义分类 → journal 留账 → 影响分析（0 token，兜住一切「绕过」）。
3. **分阶段固定 ≠ 不可改**：冻结的语义是「变更需要走影响分析并留 retcon 记录」，不是锁死；300 章的书必然多次改总纲，机制必须欢迎这件事。
4. **素材三层生长**：活层（可编辑）→ 卷定版层（冻结快照）→ 使用轨迹层（谁在哪章用了哪版）；上下文只装配定版 + 活层精选。
5. **战力体系双层**：叙事规则层（软提示）+ 数值锚点层（硬校验：越级取胜必须列依据、通胀曲线对卷纲里程碑）；防「游戏感」。
6. **想象力辅助输出概念组合提案而非成品体系**：设定工坊给「可拼装的零件 + 反差钩子」，采纳权在作者，登记防爆炸。
7. **宿主可迁移**：核心价值在文件 + git + 确定性脚本；ZCode 面（插件/MCP/命令）只是交互层，保证不与 ZCode 深度耦合。
