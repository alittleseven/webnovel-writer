# 01 · 需求分析与作者主权原则

## 1. 使命陈述

> 做一个最大程度帮作者**连贯写中文网文超过 300 章**的 ZCode 插件；插件还能用 AI 辅助玄幻技能、武力值等设定创作，**支撑并帮助作者发挥想象力**；一切以作者修改为主，全流程记录作者写作习惯与喜好。

三个关键词拆解：
- **连贯 300+ 章**：这是系统工程——记忆衰减、设定漂移、伏笔失控、战力通胀、文风漂移全部随章数超线性恶化；必须靠数据结构与确定性脚本兜底，不能靠模型自觉。
- **想象力支撑**：AI 的角色是「概念组合提案者 + 一致性守护者」，不是「代笔者」；设定工坊给零件和钩子，体系由作者拼装。
- **作者主权**：作者是唯一真源；系统的全部治理机制（留账、冻结、影响分析）服务于「作者改得放心、AI 记得住」。

## 3. 作者主权七原则（治理层宪法）

**P1 作者是唯一真源**。作者对任何文件的直接修改立即生效，不经过任何 gate；写章链路的 write-gate/precommit 只约束 AI 写入路径。AI 的每次结构性写入（大纲/素材/设定/正文）都是提案（proposal），作者采纳（settle/确认）后才成为正典。

**P2 留账不拦截**。作者修改的记录机制是 `author-sync`（会话启动时 `git diff` 扫描 → 语义分类 → `作者/journal.jsonl` 追加 → 影响分析），不是实时 hook 拦截。理由：①作者不被打扰；②作者用任何编辑器改任何文件都逃不出 git 的手掌——「绕过留痕」在机制上不可能。

**P3 留账的消费者是下一次生成**。journal 不是给人看的审计日志，是学习输入与 stale 判定源：改了章纲 → 下一章上下文标记 stale 并重读；改了定版素材 → 引用章反查提示；删了伏笔 → 承诺账本同步。

**P4 冻结 = 变更走影响分析，不是不可改**。300 章的书必然多次改总纲（商业网文常态）。分阶段固定的真正语义：卷收尾把该卷依赖的大纲/素材/战力做快照（定版），后续修改定版内容时系统给出「影响清单 + 三选项裁决」（只改今后/全书 retcon/放弃），并留 retcon(N) 记录。把冻结做成锁，作者就会绕过它——那就什么都没有了。

**P5 AI 生成物默认是草稿区公民**。regen（总纲/卷纲/章纲/素材归纳）产出写入版本画廊（`regen/` 目录带版本号），永不直接覆盖当前生效版；采纳动作显式且留账。

**P6 确定性优先**。能数的不让模型估：时间线单调性、字数、伏笔逾期、战力锚点越级、命名冲突、素材引用计数——全部脚本硬校验；模型只负责语义判断（这章是否回应了钩子）。

**P7 宿主无关的内核**。正典=文件+git；合同/索引/缓存=编译产物（可删可重建，v7 已验证此不变量）；ZCode 插件面（skills/MCP/命令）只是交互层。任何宿主（ZCode/Claude/CLI）都能驱动同一套书仓。

## 4. 非目标（明确不做）

- 不做实时编辑器内嵌 UI / 大前端（素材工作台以「按需启动的本地只读+确认面板」为上限，复用 dashboard 形态）；
- 不做多人协作 / 云同步（单作者单机）；
- 不做自动定价/发布平台对接（发布是作者与平台的事）;
- 不在本方案内重写写章主链（v6/v7 双链保持；升级以「并轨增强」方式进行）；
- 不引入数据库作为正典（SQLite 只作索引/缓存，继续遵循「派生物可丢弃」不变量）。

## 5. 关键张力与裁决预告

本方案存在四组天然张力，全部在 [03 批判性思考](03-critical-thinking.md) 展开，此处预告结论：

| 张力 | 裁决 |
|------|------|
| 作者主权 ↔ 生成效率（确认淹没） | 确认只发生在阶段边界；章内级零确认 |
| 冻结 ↔ 300 章长期演化 | 冻结=影响分析门，非锁；retcon 事务化 |
| 素材成长 ↔ 上下文预算 | 三层模型+使用轨迹+material-review 淘汰；上下文只装定版+活层精选 |
| AI 设定生成 ↔ 作者想象力 | 工坊出零件不出成品；提案采纳率为健康指标 |

## 6. 成功标准（可验证）

1. **连贯性**：以 fantasy01 续写为验收场——连续 10 章新章零「设定/时间线/战力」blocking issue；伏笔逾期扫描零漏报（构造用例）；战力越级取胜 100% 带依据。
2. **作者主权**：作者直接编辑任何文件 → 下次会话 journal 有记录且影响分析正确；改定版素材 → 收到三选项裁决；全程无一次「作者被 gate 拦截」。
3. **设定工坊**：四生成器各产 5 组提案，作者采纳≥1 组进入正典且登记完整；「生成即登记」零漏登。
4. **学习闭环**：author_model/style_profile 从 10 章修改行为中产出可读画像；注入后新章文风一致性（prose 指标）可测提升。
5. **300 章规模演练**：以脚本合成 300 章规模的书仓（扩展现有迁移仓），doctor/timeline/伏笔扫描/素材装配全部在分钟级完成，无超线性退化。
