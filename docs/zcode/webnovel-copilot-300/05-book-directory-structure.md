# 05 · 维护一本书的完整目录结构

> 基座：v7 story-repo 实跑形态（fantasy01）+ A 线六域契约 + 织机 Loom 文风域借鉴，经批判一/三轮修正后定稿。
> 作者日常只碰四处：`大纲/`、`素材/活/`、`定稿/正文/`（AI 写、作者可改）、`设定/`。其余为编译产物或系统域。

## 1. 六域总图


## 2. 关键目录语义

### 2.1 总纲三区（一个文件内的结构约定）

```markdown
# 总纲
## 甲区 · 已写卷详案（冻结区）        ← 第1~N-1 卷的详案快照，修改触发 impact+retcon 流程
## 乙区 · 当前卷活跃区                ← 第 N 卷详案，作者/AI 自由迭代，regen 只作用于此区
## 丙区 · 未来卷锚点（每卷 ≤10 行）    → 升级为详案时展开（从锚点扩写，走 regen 画廊）
```

### 2.2 素材三层流转

`活/`（作者编辑+AI 归纳追加+拆书投喂）→ 卷收尾 `freeze` → `定版/v{NN}/`（快照+manifest）→ 写作装配只取「定版+活层精选」；`使用轨迹.jsonl` 记录每章消费；`material-review` 每卷出淘汰/合并建议。

### 2.3 系统域的 git 策略

```gitignore
# 书项目 .gitignore
.cache/
工作区/
.webnovel/tmp/
.webnovel/logs/
# .story-system/ 与 .webnovel/index.db 是否入库：默认入库（体积可控、便于换机），
# 但 doctor 提供「重建对账」校验两者与正典一致 —— 漂移即报错。
```

## 3. 与既有形态的迁移映射

| 旧（v6/v7 现状） | 新（本方案） | 迁移 |
|------------------|-------------|------|
| `大纲/总纲.md`（平铺） | 三区结构 | `author-sync` 首跑自动分区（按已写卷号切分） |
| `.story-system/`（写前真源） | 编译产物 | 无数据迁移；改定位与生成方向 |
| `设定集/风格契约.md` | `文风/宪法.md` | `migrate` 子命令平移 |
| v6 override_ledger / v7 决策卡豁免 | `大纲/条目/` 承诺账本 | `migrate` 从 commit/合同抽取播种 |
| `设定集/力量体系.md` | 保留 + 抽取 `力量锚点.yaml` | 锚点抽取器（半自动，作者确认） |
| 插件 `references/csv/` | `素材/活/` 播种 | init 时按题材复制子集 |
| `project_memory.json`（.webnovel 内） | `作者/author_model.md` + `文风/指纹.yaml` | `migrate` 平移 patterns 为 author_model 播种 |

## 4. 300 章增长预估（容量设计依据）

| 资产 | 每章增量 | 300 章规模 | 说明 |
|------|---------|-----------|------|
| 正文 | 1 文件 ~2.5KB×字数（约 8-12KB） | ~300 文件 / ~3MB | git 可轻松承载 |
| 章摘要 | ~0.6KB | ~180KB | L2 层 |
| journal 事件 | 0-3 行/章（作者修改频率） | ~2-5MB jsonl | append-only，按卷归档选项 |
| 使用轨迹 | 2-4 行/章 | ~150KB | — |
| 素材活层 | 净增 0-2 条/章（含淘汰） | 稳态 200-400 条 | material-review 控制上限 |
| 定版快照 | 每卷一份活层快照 | ~30 卷 × 活层体积 | git 存量存储，可接受 |
| 条目（伏笔等） | 净增 0-1 条 | 稳态 open ≤20 条 | 逾期扫描强制收敛 |
| index.db / .cache | 线性 | ~50-100MB | 编译产物，可删重建 |

结论：纯文本+git 的容量曲线在 300 章规模完全可控；唯一需主动治理的是活层素材与 open 条目数量（material-review/逾期扫描即为此设计）。
