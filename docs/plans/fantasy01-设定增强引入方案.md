## 二、引入路径：四个动作

### 动作一：修正题材路由（10分钟，先做）

state.json 中 `genre: "都市"` 但 `genre_label: "都市+仙侠+科幻"`。当前路由会让 context-agent 拿到 urban-power 的节奏参数而非 xianxia 的。

改法二选一：

- **方案A（推荐）**：把 state.json 的 genre 字段改为 `"仙侠"`。story-system 路由和 CSV 题材过滤走修真线。
- **方案B**：不改 state，每次手动调用 story-system 时传 `--genre 仙侠`。

方案A一劳永逸，影响很小（题材标签主要影响检索过滤和节奏建议）。

### 动作二：部署插件侧新增文件（半天）

把增强方案中的 Phase 1 和 Phase 2 文件加到插件目录：

```
webnovel-writer/templates/output/schema-technique.json    ← 招式Schema
webnovel-writer/templates/output/schema-equipment.json    ← 装备Schema
webnovel-writer/templates/output/schema-resource.json     ← 地宝Schema
webnovel-writer/templates/output/设定集-武技卡.md          ← 四维模板
webnovel-writer/references/csv/武技设计.csv                ← 设计原则
```

只加文件不改代码，对 fantasy01 项目零风险。

### 动作三：存量回填（核心工作，一个下午）

#### 苏小白的能力卡（必须做，4张）

| 卡片名 | 类型 | 当前状态字段来源 |

这四张卡不符合标准招式的"攻伐/防御/身法"分类。「裂」可标为攻伐，但吞灾转化是系统级机制而非招式。

建议给吞灾转化单独建一张扩展卡，用 EquipmentCard Schema 的 growth_path 追踪熔炉本身的进化线（level 1 → 后续形态）。熔炉是这本书真正的"主角装备"。

## 三、特殊注意事项

### 这本书的技能体系是非标的

标准玄幻是"角色会N个招式"，但这本书的设计是"金手指驱动的能力成长"。「裂」不是学来的技能，是吞核后的副产物。

这意味着：
- Technique Schema 的 `min_realm` 字段对他意义不大（能力成长跟着灾痕和熔炉等级走）
- `counters_what` 更重要的是标注"什么类型的敌人/环境下有效"
- 熔炉本身需要独立的"系统进化卡"

回填时允许对模板做合理裁剪：保留四维核心（意象/机制/视觉/代价），删减不适用的字段。

### 混合题材的检索策略

实际是"末世背景 + 修真体系"。Phase 3 词根池部署后，为这本书定制专属词根倾向：偏向"灾·蚀·噬·烬"等灾厄意象而非传统仙侠的"剑·丹·符"。可在词根池CSV的"适用风格"列标注"末世修真"。
