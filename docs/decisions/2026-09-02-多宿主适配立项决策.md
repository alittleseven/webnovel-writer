# ADR · 多宿主适配立项决策

> 日期：2026-09-02；任务位：[单线队列 S20（E5 收尾）](../plans/2026-08-30-v7-单线执行队列.md)
> 背景 spec：[多宿主与多智能体适配 Spec（2026-06-05，基线 v6.1.0）](../architecture/multi-agent-adaptation-spec-2026-06-05.md)
> 既有约束：[status-and-pending-work](../plans/2026-08-25-status-and-pending-work.md)——「仅在 v7 垂直切片稳定后，先选择一个宿主建立 adapter、support.md、生成器和 smoke test；不同时铺开多个宿主」。

## 决策

**立项：是。排期：v7.0.0 发版（S21）之后，独立开新队列，本队列不含实施。首期范围：单宿主 = ZCode，仅做 adapter 正式化（support.md + smoke test + 生成器 drift check），不铺开第二个宿主。**

## 理由

1. **时机**：v7 主轴（Story Repo / v7_write）刚完成首次垂直切片实跑，写路径只被一章验证过。此刻启动 adapter 会把生成器与验收绑在一个还在变动的架构上；先让 v7.0.0 落地收敛。
2. **spec 基线过期**：现有多宿主 spec 以 v6.1.0 为基线。v7 引入 story-repo 目录契约、决策卡-机检-settle 写路径、v7_cache——多宿主实施前必须先出 **v7 基线增补**，否则 adapter 复用的是将被绞杀迁移淘汰的 v6 面。
3. **首期宿主选 ZCode**：ZCode 是**事实上的第二宿主**——插件市场装机（v6.5.0）已在 ZCode 日常运行（本仓库的开发会话即经 ZCode 执行），兼容性已被使用事实验证，正式化成本最低、收益即时；对照 spec 的 adapter 模式（只调 `webnovel.py` 不复制 runtime）风险可控。
4. **备选与否决**：Codex 适配延后（无实际使用牵引）；多宿主并行铺开否决（2026-08-25 既有约束，维持）。

## 进入条件（新队列开工 gate，三条同时满足）

1. S21 完成：v7.0.0 正式发版并装机。
2. 第 38 章以独立新会话完成 v7 链路首写，干净计量回填[切片复盘 §3.1](../reports/2026-09-02-S20-v7垂直切片复盘.md)（同时关闭 M3 的「有条件达标」）。
3. 多宿主 spec 完成 v7 基线增补（story-repo 契约 / v7_write 写路径 / v7_cache 查询面的差异清单）。
