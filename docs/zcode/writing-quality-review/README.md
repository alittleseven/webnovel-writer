# 写作质量专项审阅 · 任务文档集

> 任务名称：`writing-quality-review`
> 审阅日期：2026-09-03 · 审阅对象：`tmp/zcode` 分支 v7.1.0（webnovel-writer 插件全量）
> 审阅准绳：**只以「生成章节的文章质量」为唯一标准**——不考虑时间成本、不考虑 token 消耗。凡「为了省上下文/省往返而牺牲成稿质量」的设计，在本审阅中一律视为可优化项。
> 方法：主会话精读核心质量链（write SKILL + 3 个 agent + 润色/Anti-AI 细则）+ 3 路并行深探（技法资产盘点 / 上下文组装机制 / 度量回路与学习闭环），全部结论附 `file:line` 证据。

## 核心结论（TL;DR）

**这套系统已经把「不写崩」做到了很高水准，但「写得好」还缺乏系统化支撑。**

- 强项（保留不动）：合同树（大纲即法律/设定即物理）、5 维事实审查、write-gate 三段门禁、机检与断点续跑、双格式守卫——事实一致性、时间线、设定物理的保障是工业级的。
- 弱项（本审阅的全部优化空间）集中在六个断点：
  1. **起草模型看不到上一章原文**（只有 500 字二手摘要），文气与口吻连续性无从谈起；
  2. **文笔质量无任何系统度量**——reviewer 明确排除文笔维度，ai_flavor 是死链，Anti-AI 终检是自报契约；
  3. **一轮成稿无迭代**——起草一次、审查一轮、修复后不复审；不考虑 token 成本时这是最大的质量杠杆闲置；
  4. **反馈回路断源**——追读力/钩子/爽点指标表有消费端无生产端，审查得分趋势不在主写作路径的上下文里；
  5. **文风记忆最先被丢**——author_style_patterns 排在上下文丢弃顺序第 2 位；
  6. **技法资产接线断点**——对话声线正反例库、金手指模板库（473 行）、欲念描写专文（311 行）等已生产资产从未进入生成链路。
