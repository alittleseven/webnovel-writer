# 设定卡契约（Markdown 卡片，任意书项目可复用）

> 来源：fantasy01 实验（S15 验证通过，见 `docs/reports/2026-08-31-S15-设定卡验证与通用化决策.md`）。本契约固化目录结构、字段与读取规则；插件已内置按需读取，无需代码变更。

## 1. 目录结构

```text
设定集/增强设定/
├── 索引.md            ← 一张总表：名称 | 类型 | 状态 | 主要用途 | 来源
├── README.md          ← 使用说明（可选）
├── 能力/<能力名>.md    ← 金手指/功法/异能
├── 物品/<物品名>.md
├── 资源/<资源名>.md
└── 战力锚点/<锚点名>.md ← 势力/人物/境界的战力参照物
```

## 2. 卡片字段（三态分层，必须遵守）

每张卡为一个 Markdown 文件，核心是把事实按三态分层：

- **已确认事实**：正文已发生或卷纲已锁定的事实——reviewer 可作为审查依据，writer 必须遵守。
- **规划设定**：计划中的走向——只能用于发现潜在冲突，**不得写成已发生事实**。
- **待确认**：想法——不进入任何校验。

条目粒度要求：细到可核对（如「武器本体有损坏和耐久限制」而不是「武器很强」）。fantasy01 的 `物品/半截撬棍.md`（使用边界条目曾在 ch26 审查中作为证据拦截无条件全力一击）是格式范本。

## 3. 索引格式

`索引.md` 用一张表列出全部卡片，并附「读取原则」：写作或审查某章时，只读取本章关键实体对应的卡片；卡片不能覆盖章纲、合同或已确认事实。

## 4. 读取规则（插件已内置）

- `context-agent` / `reviewer` / `webnovel-plan` 已按需读取：仅当本章关键实体命中卡片时展开，未命中不读。
- reviewer 将「已确认事实」条目作为设定一致性维度的核对基线，可引用卡片路径作为问题证据。
- 上下文成本可控：卡片按需命中展开，不整目录加载。

## 5. 新书启用步骤

1. 在书项目 `设定集/增强设定/` 按上述结构建目录与 `索引.md`。
2. 从设定集中挑「易漂移且高频引用」的实体先建卡（建议首批：金手指能力、主战物品、战力天花板、核心资源各 1-2 张）。
3. 正常写作；新能力/物品出现时增量建卡并同步索引。
4. 不要把卡片当设定集本体——卡片是「已确认事实的核对层」，设定集原文仍是第一手来源。
