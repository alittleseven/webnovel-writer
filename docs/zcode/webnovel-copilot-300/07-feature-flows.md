# 07 · 功能实现流程文档（14 个核心流程）

> 每个流程：触发 → 步骤 → 产物 → 异常分支。标注涉及的新命令/数据。全部流程内核先 CLI 实现，ZCode 面（skill/hook/MCP）只做触发与呈现（P7）。

## F-01 · author-sync（修改触发记录 · 主入口）

**触发**：会话启动 hook（自动）或 `/webnovel:sync`（手动）。
**步骤**：
1. `git diff` 上次 journal 水位 → 工作区+HEAD（含作者用任何编辑器的修改）；
2. 脚本分类：按路径映射六域 + diff_stat 判 change_kind（add/delete/structure）→ journal 追加（无 summary）；
3. 语义补全（一次 LLM 批量调用）：为新事件生成 `summary` 与 content/style/fact 细化；
4. stale 标记：章纲/定版素材/设定/时间线修改 → `stale.json` 相应条目；条目删除 → 承诺账本同步提示；
5. 影响摘要：本次改动波及的章节/素材/校验，生成 ≤10 行作者语言摘要（会话开场注入）。
**产物**：journal 新事件、stale.json、影响摘要。
**异常**：diff 巨大（>100 文件）→ 提示可能是迁移/重排，请求作者确认整批归为 `migration` 事件。

## F-02 · 总纲分阶段管理与 regen 画廊

**触发**：`/webnovel:plan 总纲` 或作者要求改总纲。
**步骤**：
1. 读总纲三区 + 已写卷号 → 确定操作区（丙区锚点扩写 / 乙区迭代；甲区改动转 F-07 retcon 流程）；
2. regen：生成新版本 → `大纲/regen/总纲/v{N}.md` + 与当前生效版 diff 报告（画廊永不覆盖）；
3. 作者浏览（≤3 版并排 diff）→ `regen adopt v{N}` 采纳 → 写回 `总纲.md` 对应区 + journal(adopt) + 演化事件；
4. `master-outline-sync` 重编译合同（只编译活跃区）。
**产物**：画廊版本、采纳记录、重编译合同。
**异常**：采纳影响已写卷（如丙区改动波及甲区设定）→ impact 先行，列受影响章清单。

## F-03 · 卷纲时间线视图

**触发**：plan 产出卷纲后（自动）/ `/webnovel:plan 时间线 N`。
**步骤**：
1. `timeline-check` 升级版：读卷纲+章纲卡时间锚+条目伏笔点+战力锚点事件 → 推演故事内时间轴（含年龄/修龄，A4）；
2. 导出 `大纲/卷纲/第NN卷-时间线.md`（表格：章 | 故事内时间 | 事件 | 伏笔点 | 战力锚点 | 倒计时）；
3. 单调性/倒计时算术校验（现有能力）+ 与上一卷时间线衔接校验；
4. 作者直接编辑该视图 → 下次 author-sync 识别（domain=卷纲）→ 反向同步回章纲卡时间锚（列 diff 请作者确认）。
**产物**：时间线视图、校验报告。

## F-04 · 章纲批量生成与单章 regen

**触发**：`/webnovel:plan 拆章 N卷`（批量）或 `/webnovel:plan 章纲 39`（单章）。
**步骤（批量）**：
1. 输入：卷纲详案 + 条目账本（本卷应推进项）+ 总纲乙区 → 一批 ≤8 张章纲卡（front matter 见 06 §2）；
2. 批内自检：节点覆盖卷纲节拍、时间锚单调、承诺推进分布不堆积、素材引用存在性；
3. **一次确认**：作者整批审阅（表格摘要呈现 8 张卡的目标/节点/钩子）→ 逐张可改（编辑直接改文件）→ `plan confirm-batch` 统一确认（journal 一条 batch 事件）。
**步骤（单章 regen）**：同 F-02 画廊机制，≤3 版 + diff；采纳后 journal + 合同重编译。
**产物**：`大纲/章纲/NNNN.md`（状态 confirmed）、journal、合同。

## F-05 · 素材流转（活层 → 定版 → 轨迹）

**入口三个**：
- 作者手写：直接编辑 `素材/活/*.csv`（author-sync 留账）；
- AI 归纳：写章/settle 后从本章正文提炼候选条目（打 `来源:AI归纳`）→ **先进画廊**（`素材/regen/`）作者采纳才入活层；
- 拆书投喂：`/webnovel:materials 拆书 <文本>` → deconstruction-agent 抽零件 → 画廊同上。
**冻结**：卷收尾 F-10 freeze 一并快照活层 → `定版/v{NN}/` + manifest。
**使用**：写作装配只取「定版（带版本）+ 活层精选 top-K」；settle 后 data-agent 写使用轨迹。
**修改定版**：转 F-07。

## F-06 · material-review（素材卷审）

**触发**：卷收尾（freeze 后）/ `/webnovel:materials 审`。
**步骤**：
1. 脚本统计（0 token）：各条目使用率/最近使用章/来源分布/衰减标记（N 卷未用）；
2. LLM 建议（一次调用）：同义合并候选、过时淘汰候选、缺口提示（本卷写作中检索未命中过的主题）；
3. 呈现清单 → 作者逐项裁决（保留/合并/归档/删）→ 执行 + journal。
**产物**：素材健康报告、裁决记录、更新后的活层。

## F-07 · 定版修改与 retcon（冻结变更裁决）

**触发**：author-sync 识别 frozen 文件被改。
**步骤**：
1. `impact <file>`：使用轨迹反查受影响章；锚点/条目/合同依赖反查；
2. 三选项呈现（附影响清单）：①只改今后（定版不动，新章用新规则——记录例外）；②全书 retcon（生成逐章修改清单 → 作者执行或 AI 辅助执行 → 每处修改 journal）；③放弃还原；
3. 执行选定项 → journal(retcon) + 演化 `retcon(N)` 事件 + git commit（事务收口）；
4. 受影响章重跑一致性校验（reviewer 抽查 or 全查由作者选）。
**产物**：影响清单、retcon 记录、修改执行。

## F-08 · 设定工坊（四生成器，提案模式）

**触发**：`/webnovel:forge [境界|功法|法宝|命名]` 或 init 金手指环节。
**步骤（以功法为例）**：
1. 输入装配：现有设定域 + 素材零件（金手指零件.csv/世界观零件.csv）+ 题材包 + author_model 雷点；
2. 生成 **5 组概念组合提案**（非成品）：每组 = 跨域概念拼接 + 反差钩子 + 与既有设定的差异点 + 常见度自评；
3. 写入 `设定/regen/工坊/功法-v{N}.md` 画廊；
4. 作者采纳：工坊把提案**扩写为设定文档草案**（仍走画廊二次确认）→ 登记三处同步（设定集 md + 力量锚点（若涉战力）+ 合同重编译）→ journal(adopt)；
5. 采纳率统计入 signals（<30% 连续两卷 → 工坊提示词进化进学习闭环）。
**红线**：不生成战力数值；核心金手指/主角独特性类提案标注「灵魂设定——建议作者自拟，工坊仅给反差参考」。

## F-09 · 战力校验（power-check）

**触发**：review 环节（每章自动）/ `/webnovel:power`。
**步骤**：
1. 读锚点表 + 本章战例（data-agent 提取）；
2. 硬校验：跨阶依据完备性、与境界链矛盾；
3. 软校验：通胀曲线 vs 卷纲里程碑（偏差>阈值提示）；
4. 结果进 reviewer 证据源 + 越级战例账本回写。
**产物**：校验报告、账本更新。

## F-10 · 卷收尾冻结（freeze）

**触发**：作者发起（`/webnovel:freeze N`）或 backup --volume 后提示。
**步骤**：
1. 前置检查：本卷章全部 settled、伏笔逾期扫描清零或显式豁免、stale 清空；
2. 快照：大纲甲乙区扩展（乙→甲）、素材活层 → 定版 v{NN} + manifest、战力锚点 sha1 记录；
3. material-review（F-06）建议呈现；
4. git commit（freeze 事务：快照+manifest+journal+演化事件）。
**产物**：定版目录、冻结清单、事件。

## F-11 · 写章链（v7 主链 + 增强点标注）

既有：决策卡 → 上下文包 → 草稿 → 机检 → 作者验收 → settle。
**增强点**：
- 决策卡消费章纲卡（素材引用/战力事件预告/承诺推进）；
- 上下文包装配：stale_notes 前置段 + prev_chapter_tail + style_anchor + reader_signal + 定版素材（W1/W4/W6）；
- 草稿 `--drafts N` 择优（W3）；
- 机检 + prose_check（W2）+ 战力对账（预期 vs 实际战例）；
- settle 追加：使用轨迹写入、锚点/战例回写、条目状态推进、style_profile 增量更新。

## F-12 · 学习闭环（被动为主）

**信号源**：journal（作者改了什么=最强信号）+ 定稿 vs 草稿 diff + 审查指标 + 工坊采纳率。
**节奏**：每卷一次 `learn --from-journal`（归纳 author_model 更新建议 + 高分 pattern 候选，作者确认后生效）；单章级高频信号只做统计不进 LLM（token 纪律）。
**回写**：author_model.md / 文风/指纹.yaml / 跨书偏好.yaml（用户层）→ 全部进 context 装配。

## F-13 · doctor 治理层体检

新增检查组：journal 水位 vs git 状态（未留账告警）、stale 积压、定版-轨迹一致性、锚点-正文对账、条目状态机、素材健康摘要、画廊积压（>2 卷未清理）、合同编译一致性（重建对账）。

## F-14 · 素材工作台（会话模式 + dashboard 视图）

- 会话模式：`/webnovel:materials` 进素材管理对话（查/增/改/合并/裁决，全部经画廊或直接编辑+留账）；
- dashboard 视图组：总纲三区状态、冻结进度、journal 时间线、素材热力、通胀曲线、stale/逾期红点（只读）。
- 交互红线（素材工作台 UI 设计继承）：LLM 只提议、作者只确认、git 只存正典；正文域工作台只读。
