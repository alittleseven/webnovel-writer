## 3. 推导：配额应该设多少

**推导原则**：context-agent 的产出（五段任务书）约 3,000-5,000 tokens；输入包按「产出的 3-4 倍」供给即可支撑任务书五个段落，且每一段都要有明确数据来源、不设无用上限：

| 任务书段落 | 数据来源 | 配额（字符） |
|---|---|---:|
| ① 硬约束 | chapter_directive 586 + review 677 + master 核心 2,794 | story_contracts **8,300**（master 2,800 / volume 1,000 / chapter 3,500 / review 1,000） |
| ② 节点 | outline（已有 1,500 上限） | — |
| ③ 前情 | recent_summaries 1,000 + urgent_loops 1,200 + recent_changes 1,500 + protagonist 1,500 + progress 800 | — |
| ④ 风格 | style_contract 2,000 + author_style_patterns 2,000 + genre_profile_excerpt 1,500 | — |
| ⑤ 长期事实 | semantic_memory 3,500 + active_rules 1,200 + episodic 1,000 + state_export 2,500（working 内） | memory_pack **8,500** |
| 上一章衔接 | runtime_status 仅 meta + projection_status + summary_text | runtime_status **700** |

**全满合计 ≈ 29,200 字符；fantasy01 实际场景（genre/style 三节缺席）≈ 23,200 字符。**

**总预算默认 = 20,000 字符（≈15-18k tokens）**，理由：
1. 旧签名默认 `budget_tokens=4000` 太小——仅为当前真实体积的 7%，硬执行会砍掉合同与记忆，违反「覆盖一致」红线；分析后弃用，签名参数改为显式覆盖入口。
2. 20,000 对 fantasy01 当前 59,977 字符为 **−67%**，且全部砍在 §2 判定为冗余的内容上（latest_commit 全文、source_trace、dynamic_context 超额、state_export 超额），零信息损失风险点都有替代来源。
3. 超总预算的丢弃顺序按价值递减：`episodic_memory` → `author_style_patterns` → `genre_profile_excerpt` → `progress` → `active_rules` → `recent_summaries`（保留）……硬约束类（story_contracts、outline、semantic、urgent_loops）最后动。

## 4. 预期收益 → 实装后实测（2026-08-30）

| 指标 | 实装前 | 分析预期 | **实装后实测** |
|---|---:|---:|---:|
| load_context 总体积（ch35） | 59,977 字符（≈45k tokens） | ≤20,000 | **19,241 字符（−68%）** |
| 其中 latest_commit | 23,427 | ≤700 | **830（runtime_status 全节，含 meta+摘要）** |
| 其中 source_trace×2 | 4,508 | 0 | **0** |
| `budget_used_tokens` | 恒 0（死值） | 真值 | **19,241（真值）** |

实装后各 section 键结构验证：latest_commit 仅剩 meta/projection_status/extraction_summary；master 保留 route/master_constraints/base_context/meta；chapter 保留 chapter_directive/meta/override_allowed/reasoning/dynamic_context（截断保留）。

叠加意义：这是**每次写章 context-agent 必读的基础包**，−68% 直接作用于每一章；同时任务书信息密度上升（冗余键不再稀释注意力）。

## 5. 覆盖一致性红线

预算截断只允许砍 §2 判定为「冗余/元数据/已蒸馏」的内容；任务书五段的数据来源（§3 表）为保护对象。验收沿用 round1 审计口径：**同书同章，实装前后任务书的事实/约束/伏笔覆盖逐项一致，仅 token 下降**——在 fantasy01 第 36 章写作时人工比对一次。
